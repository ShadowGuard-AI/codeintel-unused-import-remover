One File at a Time

The program removes unused import statements from one Python file. A file path is required; nothing runs without it. The file is read and the code is parsed with ast. Every Name identifier is collected as a use. Import and ImportFrom nodes supply the bindings. An alias binding is its asname, or the first part of its dotted name. A star import is skipped, since it binds names this pass cannot list. The code uses the standard library only.

Names That Count as Used

Names inside string constants also count as used, so a lazy path, an export list, and a getattr target survive a plain run. The option named aggressive drops that string net, and indirect uses may then be removed. An unused import on a line with another statement is skipped and logged as skipped; a semicolon line counts as shared, removal takes whole lines only, one used alias on a line saves the whole line, and a parenthesised import spanning several lines is removed across its whole span.

The Backup Comes First

On a dry run no file changes, the parse check still runs first, and a rewrite that would not parse fails the dry run too; removals are listed in the log. On a writing run the rewritten text is parsed before writing and failure means no write. A backup is copied first, its name being the file name plus the suffix .bak. An existing backup stops the run, the exit is 1, and the file stays untouched.

How a Run Can End

Missing file: 1. Unreadable file: 1. Syntax error in the source: 1. Backup or write failure: 1. Success: 0. A non Python suffix draws a warning and the run proceeds anyway.

# codeintel-Unused-Import-Remover

Removes unused import statements from Python code to reduce code clutter and improve readability. - Focused on Tools for static code analysis, vulnerability scanning, and code quality assurance

## Install

`git clone https://github.com/ShadowGuardAI/codeintel-unused-import-remover`

## Usage

`./codeintel-unused-import-remover [params]`

## Parameters

- `-h`: Show help message and exit

- `--dry-run`: Perform a dry run without modifying the file.

- `--aggressive`: No description provided

## How a run changes your file

A run that is not a dry run rewrites the named file in place. Before it writes, it saves a backup copy next to the target with a `.bak` suffix (for example `app.py.bak`) and logs that path. If a backup with that name already exists, the run refuses to modify the file and exits 1, because that backup may be the only copy of an earlier original. Move or rename the old backup if you want to run the tool on that file again. The rewritten text is parsed before it is written, and a run whose file cannot be written exits 1. An import that shares a line with another statement, for example behind a semicolon, is skipped for safety and listed as skipped in the log.
